# FileDownlink Component

## Overview

The `FileDownlink` component is an active F´ component that manages spacecraft file downlink operations. It provides a robust mechanism for downloading files from the spacecraft to the ground station by dividing files into packets and managing a queue of pending downloads.

## Key Features

- **File Queuing**: Queue multiple files for downlink from different sources
- **Packet-based Transfer**: Automatically divides files into packets for reliable transmission
- **Command Interface**: Operators can initiate file downloads via ground commands
- **Port Interface**: Components can programmatically request file downloads
- **Partial Downloads**: Support for downloading specific portions of files
- **Cooldown Management**: Configurable delays between downloads to prevent link saturation
- **Timeout Handling**: Automatic timeout detection and recovery

## Component Configuration

Before using the FileDownlink component, it must be configured with the following parameters:

```cpp
void configure(U32 timeout, U32 cooldown, U32 cycleTime, U32 fileQueueDepth);
```

- **timeout**: Maximum time to wait for buffer returns (milliseconds)
- **cooldown**: Delay between file downloads (milliseconds)
- **cycleTime**: FileDownlink Run_handler run-time(ms) per call.
- **fileQueueDepth**: Maximum number of files that can be queued

## API Reference

### Commands

#### SendFile
Download a complete file from the spacecraft.

```
SendFile(sourceFileName: string, destFileName: string)
```

**Parameters:**
- `sourceFileName`: Path to file on spacecraft - /absolute(OS) or relative(posix) (max 100 chars)
- `destFileName`: Suggested destination filename for ground station (max 100 characters)

**Example:**
```
SendFile "/opt/data/telemetry.log" "spacecraft_telemetry_20250717.log"
```

#### SendPartial
Download a portion of a file starting from a specific offset.

```
SendPartial(sourceFileName: string, destFileName: string, startOffset: U32, length: U32)
```

**Parameters:**
- `sourceFileName`: Path to the file on the spacecraft - absolute or relative (max 100 characters)
- `destFileName`: Suggested destination filename for ground station (max 100 characters)
- `startOffset`: Starting byte offset in the source file
- `length`: Number of bytes to download (0 = until end of file)

**Example:**
```
SendPartial "/opt/data/large_log.txt" "log_excerpt.txt" 1024 2048
```

#### Cancel
Cancel any file downlink currently in progress.

```
Cancel()
```

### Port Interfaces

#### SendFile Port (Input)
Components can programmatically request file downloads using this port.

```cpp
Svc::SendFileResponse SendFile_handler(
    const FwIndexType portNum,
    const Fw::StringBase& sourceFilename,
    const Fw::StringBase& destFilename,
    U32 offset,
    U32 length
);
```

**Returns:** `SendFileResponse` containing:
- `status`: `STATUS_OK` or `STATUS_ERROR`
- `context`: Unique context ID for tracking the request

#### FileComplete Port (Output)
Notifies connected components when a file download completes.

**Usage:** Connect this port to components that need to know when their file download requests complete.

### Telemetry

The component provides the following telemetry channels:

- **FilesSent**: Total number of files successfully downloaded
- **PacketsSent**: Total number of packets transmitted
- **Warnings**: Total number of warnings encountered

### Events

Key events generated by the component:

- **FileSent**: Successfully completed a file download
- **DownlinkCanceled**: File download was canceled
- **DownlinkTimeout**: Download timed out and was canceled
- **FileOpenError**: Could not open the specified file
- **FileReadError**: Error occurred while reading the file

## Usage Examples

### Basic File Download (Ground Command)
```
# Download a complete log file
SendFile "/opt/logs/system.log" "system_log_backup.log"
```

### Partial File Download (Ground Command)
```
# Download the last 1MB of a large file
SendPartial "/opt/data/huge_dataset.bin" "dataset_tail.bin" 104857600 1048576
```

### Programmatic File Download (Component)
```cpp
// In your component's implementation
Fw::LogStringArg sourceFile("/tmp/sensor_data.csv");
Fw::LogStringArg destFile("sensor_data_20250717.csv");

// Request file download with full file (offset=0, length=0)
Svc::SendFileResponse response = this->fileDownlinkOut_out(0, sourceFile, destFile, 0, 0);

if (response.status == Svc::SendFileStatus::STATUS_OK) {
    // Store the context ID to track completion
    this->m_downloadContext = response.context;
} else {
    // Handle error
    this->log_WARNING_HI_FileDownloadFailed(sourceFile);
}
```

### Handling Download Completion
```cpp
// Connect to FileComplete port to receive notifications
void MyComponent::fileComplete_handler(
    const FwIndexType portNum,
    const Svc::SendFileComplete& resp
) {
    if (resp.context == this->m_downloadContext) {
        if (resp.status == Svc::SendFileStatus::STATUS_OK) {
            this->log_ACTIVITY_HI_FileDownloadSucceeded(resp.sourceFilename, resp.destFilename);
        } else {
            this->log_WARNING_HI_FileDownloadFailed(resp.sourceFilename);
        }
    }
}
```

## Integration Guidelines

### Required Connections

1. **Scheduler**: Connect `Run` port (Run_handler) to a rate group for periodic execution
2. **Buffer Management**: Connect `bufferSendOut` and `bufferReturn` ports for packet transmission
3. **Command Interface**: Connect standard command ports (`cmdIn`, `cmdRegOut`, `cmdResponseOut`)
4. **Events and Telemetry**: Connect `eventOut` and `tlmOut` ports
5. **Time**: Connect `timeCaller` port for timestamp generation

### Configuration Recommendations

- **Timeout**: Set based on expected packet round-trip time (typically 30-60 seconds)
- **Cooldown**: Configure based on link capacity and other traffic (typically 5-30 seconds)
- **Cycle Time**: Match your rate group period (typically 1000ms)
- **Queue Depth**: Size based on expected concurrent download requests (typically 10-50)

### Best Practices

1. **Monitor telemetry** regularly to track download performance
2. **Use partial downloads** for large files to reduce transmission time
3. **Implement timeout handling** in components using the SendFile port
4. **Queue management**: Avoid overwhelming the queue with too many simultaneous requests
5. **File size limits**: Component supports files up to 4GiB maximum

## Error Handling

The component handles various error conditions:

- **File not found**: Generates `FileOpenError` event
- **Read errors**: Generates `FileReadError` event with status code
- **Timeouts**: Automatically cancels download and generates `DownlinkTimeout` event
- **Queue full**: SendFile port returns `STATUS_ERROR`

Monitor the `Warnings` telemetry channel and component events for error detection and debugging.

## Thread Safety

The FileDownlink component is thread-safe and uses internal mutexes to protect shared state. Multiple components can safely call the SendFile port concurrently.
